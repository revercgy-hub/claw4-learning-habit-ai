## Fault requirements vs present evidence

`m1_round_evidence.py` defines eight formal fault checks: `nas_disconnect_recovery`, `websocket_reconnect`, `tts_midstream_network_loss`, `silence_timeout`, `wake_without_asr`, `repeated_interruptions`, `self_capture_during_tts`, `self_capture_after_tts`. Each is independently `PASS`, `FAIL`, or `NOT_VERIFIED`; absent/unknown becomes `NOT_VERIFIED`. Formal summary is `NOT_VERIFIED` when checks are missing. Round flags also record misrecapture, stuck, crash, WDT, reboot, looping capture, and lost response.

Available preflight evidence: NAS same-window event classification shows one ASR_RESULT + matching LLM_INPUT; later end-prompt LLM_INPUT matches reviewed fallback prompt and configured 120 s silence-close behavior, supporting scheduled close rather than a second spoken question. Captured window reports no HTTP 403, traceback, interrupt, or crash markers and NAS restart count 0. These observations are scoped evidence, not PASS for the formal fault matrix: there was no deliberate fault injection, nor full round-bound outcomes for reconnect, midstream loss, wake-without-ASR, repeated interruption, or self-capture during/after TTS. Silence-timeout evidence supports the observed normal close path only.

AP outage/recovery remains `SKIPPED_BY_USER / NOT_VERIFIED` per [M1 plan](V6_M1_XIAOZHI_NAS_VOICE.md); do not redispatch it or relabel it NAS-verified. Do not propose a first fault operation that writes/erases NVS, flash, or persistent state. Any future fault collection must remain inside separately authorized scope.
