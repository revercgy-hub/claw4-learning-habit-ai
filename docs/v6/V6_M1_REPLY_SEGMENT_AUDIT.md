## Bounded discrimination and next action

The missing mathematical relation lies at or before the server's original segment text, **if** the normal visible-content path was active. The representation mismatch is a concrete input risk: the model received rich ASR JSON where the display showed only its `content`. Competing explanations remain the model's output under that input plus the full dynamic prompt/history, an alternate function/direct-answer path, a server-side pre-segmentation transform, or response interruption/context effects. The two identical original-text group digests make a one-off device subtitle loss less likely, but do not establish the model's raw output or actual audio. The later ASR/interruption is a separate human-input classification problem because the operator did not remain silent.

The root's plain/rich WebSocket pair already distinguishes two server outcomes under these synthetic inputs. For a causal repair decision, obtain privacy-safe role/length/hash evidence for the **actual** enhanced prompt and conversation history and compare provider visible stream, TTS queue input, original/cleaned segment text, and first audio/packet status. The existing log labels `大模型收到用户消息`, `语音生成成功`, `发送第一段语音`, and `发送音频消息` expose input or segment text, not a full raw provider response; private logs must remain private. The [text processor](E:/v6/s17-voice-l20-20261020-01/source-audit-s19-handlers/core/handle/textMessageProcessor.py#L17) accepts JSON messages; the [hello handler](E:/v6/s17-voice-l20-20261020-01/source-audit-s19-handlers/core/handle/helloHandle.py#L42) accepts optional `audio_params`/`features` and returns welcome; `listen.detect` reaches `startToChat` for non-wake text through `listenMessageHandler.py:55–116`. The [connection route](E:/v6/s17-voice-l20-20261020-01/source-audit-s19/core/connection.py#L345) enforces the bind gate. This synthetic path is HOST service evidence, never a DEVICE round.

The smallest candidate correction sits in the known SenseVoice dict branch of `ASRBase.handle_voice_stop` (`base.py:128–170`): retain `enhanced_text` for existing ASR reporting, but pass a separately validated `chat_text` to `startToChat`. For a recognized `content/language/emotion` envelope with nonempty bounded string `content`, use the content alone when no trusted speaker exists; if a speaker is verified, retain only the established `speaker/content` shape so `startToChat` keeps its current first-introduction behavior. Preserve other ASR strings and unknown dict shapes, ordinary `listen.detect` strings, wire messages and headers. `ASRBase` is shared, so the schema guard is essential; do not silently discard language/emotion metadata from reporting or change speaker ownership. This is an internal input correction that can preserve the public protocol, but Astra should approve the semantic boundary if metadata, intent or speaker ownership changes. Minimal HOST tests should cover recognized dict with/without speaker, unknown dict, plain string, empty/non-string content, unchanged report envelope, and the resulting STT/LLM input pairing; rerun the full server-path plain/envelope synthetic probes, then a controlled device preflight for a complete correct audible response. A concise M1-specific prompt template may separately address verbosity: the current default `agent-base-prompt.txt` is 6,528 bytes/6,145 characters and includes `{{base_prompt}}` once. Use a dedicated configured template that retains that placeholder, while checking path, file hash/cache state and rendered prompt before attributing any behavior change. Any change to voice ownership, barge-in policy or shared protocol belongs with Astra under ADR-001. Do not count preflight-03 toward the formal 20 or infer AEC effectiveness.
